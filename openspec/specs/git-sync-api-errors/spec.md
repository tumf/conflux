## Requirements

### Requirement: git_sync API は内部エラーでパニックしない
`git_sync` API のエンドポイントは、内部エラーに起因するパニックを起こしてはならない。すべての内部処理エラーは適切に捕捉され、HTTPエラーレスポンスとしてクライアントに通知されなければならない。

#### Scenario: 内部処理エラーは HTTP エラーとして返される
- **GIVEN** API リクエスト処理中にシステムレベル、または入力に起因するエラーが発生する
- **WHEN** `git_sync` API を実行する
- **THEN** サーバーはパニックせず処理を継続する
- **AND** クライアントには HTTP 400 番台または 500 番台の適切なステータスコードと、原因を示すエラーペイロードが返される

#### Scenario: 不正なリポジトリパスでもサーバープロセスは継続稼働する
- **GIVEN** 権限がない、または不正なリポジトリパスを指定して `git_sync` API を呼び出す
- **WHEN** git コマンドやファイルシステム操作が失敗する入力を API に送信する
- **THEN** サーバープロセスはパニック終了せず、正常に稼働を続ける
- **AND** クライアントには `500 Internal Server Error` などのエラーレスポンスが適切なメッセージ（例: `Repository not found`, `Sync failed`）とともに返される
