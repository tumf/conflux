# Web error-detail projection design

## Authority, ownership and anatomy

Production authority is `web/app.js`, `web/index.html`, `web/style.css` at `0444fd4c4f32be306f072619a1d2017393d457cb`. Precedence: this design defines the one new term/value and visibility rule; the revision defines all retained visual properties. The parent's screenshot corroborates the omission, but is not an alternative pixel authority.

Owner for every matrix row: `OperatorConsole.renderChangeRow` and `appendDetail` in `web/app.js`; input is the current v2 `ChangeResource`, `this.expanded` owns disclosure state, `web/style.css` owns all resolved visual properties. There is no new accepted command. Existing Retry remains `retry_change`, exclusively authorized by current `actions.retry_change` plus unchanged mutation availability. No field parsing can authorize recovery. Server sanitation remains `events::sanitize_detail`: up to 8,192 UTF-8 bytes including its truncation marker; newline, tab and carriage-return are already escaped by the producer. Browser must display exactly the supplied nonblank string, without a second truncation or unescaping. No global error, log or activity fallback.

Reuse `resource-details > dl > div > dt + dd` through `appendDetail`, after the Dependencies wrapper. Label is exactly `Error detail`; value is a text node, with no icon, heading, banner, nested status badge, link, button, ANSI spans, inline style, or new live-region role. Existing status/task/iteration/dependency wrappers remain in the same order. Gate asserts this actual DOM anatomy (including absence of script/img/a children inside the value), not a string fixture.

Visual properties to preserve: Details margin-top `var(--space-3)` = 0.75rem; `dl` margin 0; term color `--color-text-muted` = #b8c2d4 dark / #4a5468 light, size 0.8125rem; value margin `0 0 var(--space-2) 0` = 0 0 0.5rem 0, mono `--font-mono`, size 0.8125rem, inherited line-height 1.5 and text color `--color-text` = #f5f7fa dark / #10131a light. Value has normal wrapping with body's `overflow-wrap: anywhere`; no clamp, ellipsis, max-height, fixed width or new scrolling region. Long bounded detail grows the card and normal page scroll. Existing 40rem/64rem mobile-first breakpoints, 72rem content max, `min-width: 0`/`minmax(0, 1fr)` shrink behavior and no page horizontal overflow rules remain unchanged. Existing font roles/weight and normal whitespace behavior are retained. No theme/locale overrides: English existing console, Unicode detail literal and `translate=no` behavior on the existing change ID unchanged. No safe-area or orientation-specific new surface. Existing zoom-friendly viewport and font scaling, reduced-motion behavior and high-contrast theme remain authoritative.

Button remains `.btn.btn-secondary.disclosure`, 44px minimum target from `--touch-target`, inherited 3px focus outline from `--focus-width`. Action order and priorities stay unchanged: server-allowed Retry/other existing secondary or destructive actions precede Details; Start stays existing primary lifecycle action. No new focus target or focus trap. Native button click/Enter/Space toggles one associated container and aria-expanded; aria-controls refers to the existing unique details ID. Reading detail never submits commands or moves tabs. Closing hides detail and stays on the disclosure. Same-page refresh retains open/closed by change ID but this change does not promise focus restoration after the existing whole-list renderer replaces nodes. Full-page reload/new console starts with the existing empty Set. If a row disappears then reappears in the same console instance, its previous Set membership remains; no durable preference is written.

## Exact input/transition policy

- Test exact canonical status `error`. Append one Error detail wrapper on error rows only.
- Accept `typeof error_detail === 'string' && error_detail.trim().length > 0`; use trim only for presence, render the original string verbatim, including leading/trailing whitespace.
- Error row with absent/undefined, null, empty, whitespace-only, number, boolean, object or array: one wrapper with `Error details unavailable`. No JSON stringification and no placeholder pretending to be a cause.
- Non-error row: omit the wrapper entirely, including stale populated field; do not clear or mutate API state.
- Current row refresh replaces the value; error-to-non-error removes it, non-error-to-error adds it, open stays open and closed stays closed. Each row is isolated by ID. Current missing detail replaces a prior populated value with fallback, never retains an obsolete reason.
- Recovery is simply read reason → fix/commit outside Web as instructed by the actual diagnostic → optional existing allowed Retry. Do not derive buttons or guidance from that string. Retained HTML/ANSI-looking text is inert, not an executable repair link.

## Inventory and fail-closed coverage

`ui-matrix.json` contains stable required cases. All rows map to the owners above. Each row is required across viewport contract classes `phone` (320x640), `tablet` (768x1024), `desktop` (1280x800), `short` (568x320), and `zoom` (640x800 at 200% browser zoom). Themes are shipped dark/light; reduced motion and high contrast retain existing CSS authority. This is an inherited-rule inventory, not a claim that jsdom renders those boxes.

Implement test-side expected IDs and case registry matching the matrix IDs and `contract_version: 1` in the new test file. Carry the contract version and expected row set into that permanent test file so archive relocation cannot break the command: tests must not load an active `openspec/changes/...` path. For each executed case, collect success only after assertions have completed. A final assertion compares the executed ID multiset to the required IDs and rejects missing, duplicate, failed, stale-version, pending or `NOT_EVALUATED` rows. Tests may not use skip/todo/only or `--passWithNoTests`. The matrix is a design inventory, never prefilled test results. Tests must assert the relevant combinations, not only mark IDs as visited.

DOM integration tests import real `web/app.js`, mount `web/index.html` with styles via existing `mountConsole({withStyles:true})`, bootstrap the fixture v2 server and click the real disclosure. Snapshot updates use the existing fixture observation path, including event-gap reconciliation (see existing stream-recovery tests), rather than replacing text by hand. Keyboard local proof checks button type, focusability, association and activation handler through click; native Tab/Enter/Space observation is deliberately separate. No fake API error is needed: input is a successful state snapshot carrying the real error data shape. Fixture transport/errors are test doubles only, never product behavior.

The single gate is `npm --prefix tests/web test -- error-detail.spec.js --reporter=verbose`. It must report the selected file and at least 12 tests, with zero skipped/todo tests and no missing row. Add explicit imports of `./responsive.spec.js` and `./contrast.spec.js` from the new spec to run their existing inherited CSS gates inside this bounded selection. Use `helpers/css.js` token resolution plus concrete selector/declaration assertions for the Details/btn rules named above; prohibit new inline styles and assert inherited class/anatomy for the new value. These mechanical inherited-token tests plus DOM content detect the old omitted/generic substitute implementation, but are NOT pixel-rendering/layout evidence. Do not freeze whole-source hashes in a regression gate; unrelated future production evolution should not fail this feature test.

## Verification boundary and alternatives

No installed browser screenshot/layout harness exists in `tests/web`; package scripts have only Vitest/jsdom. Adding a second UI framework or a browser dependency for one field is rejected. Therefore pre-integration completion claims safe content, state, semantics and inherited visual-token contract only. It does not claim pixel-level visual conformance, measured overflow, native keyboard synthesis, screen-reader output or focus restoration on complete list replacement. Parent/operator may later observe a built isolated real-browser fixture across the inventory viewport classes/themes, long/unbroken/Unicode input, expanded/collapsed/refreshed/fallback/cleared states, zoom and keyboard reachability. Record actual revision/build, fixture and settled screenshots/results outside the worktree. This is non-blocking Future Work, not invented local proof or authority to touch an existing owner.

Rejected alternatives: log/activity scraping invents the wrong cause; innerHTML/ANSI interpretation adds attack surface; new modal/settings/copy UI changes independent interaction contracts; backend schema/diagnostic changes duplicate already-correct authority; queue-to-mark relabeling/dispatch changes independent selection semantics. None is necessary for the single omitted error-detail projection.
