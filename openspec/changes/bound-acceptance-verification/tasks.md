No global setting, `.cflx.jsonc` key, external cache, or out-of-worktree durable state was introduced, so constitutional law 1 holds: deleting `~/.local/state/cflx/**` changes no next action.
- Shared admission consults one classifier behind every retry alias through an injected `AcceptanceAdmissionPort`. Its default (`AlwaysAdmitAcceptance`) admits, because an assembly with no managed worktree has no fingerprint to recompute; the authoritative workspace-derived guard runs inside the Acceptance boundary itself, so a permissive port can at worst cost one bounded attempt that immediately re-refuses. The TUI binds the real workspace-derived port.
- A workspace that is not a Git working tree has no candidate revision to freeze, so it receives no manifest rather than a hold, and Acceptance there behaves exactly as it did before this change. Collapsing "never a repository" into "repository unreadable" would have turned every non-repository Acceptance into a permanent hold.
- The superseded prompt-only advisory reuse block (`build_verification_reuse_context` and its tests) was removed rather than left alongside the boundary block: two competing prompt contracts for the same decision is exactly the ambiguity this change exists to end. The reuse *machinery* (`plan_reuse`, `decide_reuse`, `RuntimeVerificationExecutor`) is unchanged and is now driven by the runtime.
- `RepositoryFacts` gained a defaulted `resolve_revision`. The default refuses rather than answering with `HEAD`, so a fact source that cannot resolve a base leaves the review range empty instead of binding evidence to a comparison nobody made.
- Test-only task-local `REVIEW_BUDGET_OVERRIDE_MS` scopes the semantic review budget to milliseconds, mirroring the existing verdict-grace override. The production partition is whole seconds and its smallest positive work budget is one second; proving the deadline fires, terminates, reaps, and settles does not need a real second of waiting.
- Observed flakiness, not caused by this change: `parallel::tests::manual_resolve::persistent_scheduler_dynamic_queue_push_after_initial_analysis_bypasses_debounce` and `parallel::tests::executor::test_manual_resolve_wait_retries_after_in_flight_apply_completes` failed intermittently (once in eight full-suite runs) under heavy concurrent load, and pass individually and in repeated runs. Neither touches Acceptance, the manifest, or any code this change modified; both assert on timing-sensitive scheduler ordering.
- Attempt-2 acceptance repair, design notes that do not fit the follow-up section's one-line form:
  - The terminal fingerprint is made stable by re-binding only the **gate artifact digests** after execution, not by rebuilding the whole manifest and not by dropping `artifact_digest` from the identity projection. Dropping it would have contradicted the spec scenario that names a changed bound artifact as restoring eligibility; a full rebuild would have spent a round of Git subprocesses reconfirming bindings `capture` already proves stable (it refuses on a dirty worktree, and refuses again if the commit, tree, automation blob, or tool digest moved while the command ran).
  - Gate deadlines are now enforced *inside* the supervisor (`CommandSupervisor::run_bounded`) rather than by a `timeout` wrapped around the capture future. Cancelling a future cannot terminate a child; the previous shape left the declared command running in the worktree while the hold claimed `cleanup_confirmed: true`. The default `run_bounded` keeps the old drop-based shape for supervisors that own no OS process, and reports `not_applicable` cleanup rather than a claim about a process that never existed.
  - A fingerprint-guarded execution hold is now retryable when the classifier admits it. The boundary emits every execution hold with `resumable: false` by construction, so the resumability guard was refusing exactly the holds the fingerprint exists to arbitrate. `ChangeRuntimeState::is_acceptance_execution_hold` scopes the exception to holds whose stable category the classifier can actually answer for; every other non-resumable stall keeps the old refusal.
  - `classify_admission` now refuses only for the three deadline categories. `RuntimeDefect` and `ManifestMalformed` say nothing about the input — worktree cleanliness is not a fingerprint component — so refusing on them turned a recoverable environment fact into a permanent refusal.
  - Evidence review binding uses `Option<ReviewBinding>` rather than two plain strings. `None` means *this caller asks no review question* (the `openspec verify` path, which has no manifest) and skips the comparison; `Some` with empty fields means *a review with no resolvable base*, which correctly mismatches an envelope recorded under a real base.
- `src/parallel/tests/run_command_scope.rs` is not named by any finding. It is changed because the regression tests added for the gate-deadline and fingerprint findings run real subprocesses, and that extra load made the pre-existing 200 ms wall-clock window in `run_fatal_error_precedes_cleanup_barrier` miss its event: the full suite failed 3/3 with the new tests and 1/4 without them. The positive half of that test now waits for the Error itself under a generous hang safeguard — which is the ordering the contract actually states — while the negative "and it still has not returned" half keeps its real window. Seven of the last eight full `cargo test --lib` runs are green.
- The end-to-end two-attempt proof (`acceptance_execution_boundary_hold_after_a_gate_ran_still_refuses_unchanged_input`) runs two complete `execute_acceptance_in_workspace` invocations against a real repository, ~1.5 s, and is marked `#[cfg_attr(not(feature = "heavy-tests"), ignore)]` under the one-second rule. The same invariant is kept in the default suite by `acceptance_execution_boundary_settled_fingerprint_survives_gate_execution` (0.93 s), which was confirmed to fail when the post-gate artifact re-binding is removed.
