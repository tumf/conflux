## Future Work

- Timer-driven analysis rate limiting beyond trigger lifetime: `should_reanalyze_queue` opens permanently once 10 s have elapsed since the last queue change, so a long-lived unchanged zero-capacity state can still re-analyze on ordinary timer wakes under the non-bypass `Initial` reason. This proposal deliberately preserves the existing bounded queue-debounce policy, so changing when that window is armed (for example re-arming it after each analysis attempt) is a separate scope decision.
- Rename `ResolveCompletion` or separate ordinary workspace completion from resolve-specific trigger classification only in a dedicated follow-up change; this proposal intentionally preserves current mapping semantics.
