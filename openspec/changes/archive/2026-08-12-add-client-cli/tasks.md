It is not part of this change's declared verification and was not regressed; the feature-disabled build and its tests are clean.
- Implementation decisions worth naming:
  - A conflicting execution mark that appears *after* the client's own mark settles is reported as `partial_intent`, not `operator_intent_conflict`. The spec's "Settled mark without Start is partial intent" scenario is explicit that a conflicting mark before Start takes the partial-intent path; a clean refusal there would imply nothing was written, and clearing either mark to restore isolation would mutate another operator's intent.
  - `evidence_error` was added to the outcome set for `Contradictory` and `EvidenceError` repository verdicts. The design's outcome list is introduced with "include", and collapsing a broken proof into `timeout` or `not completed` would hide a repository state an operator has to look at.
  - The event stream is a *wake hint* only. `wait` re-reads every authoritative resource on any wake (activity, gap, or idle), so a missed or malformed frame costs one poll interval and never an answer; the gap-recovery test drives a real ring overflow to prove it.
  - `--timeout` accepts `ms` in addition to `s`/`m`/`h`, so the deadline tests express sub-second budgets without short wall-clock thresholds standing in for correctness assertions.
