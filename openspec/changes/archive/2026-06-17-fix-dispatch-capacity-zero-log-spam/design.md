# Design: Capacity-zero dispatch diagnostic deduplication

## Current behavior

`perform_reanalysis_and_dispatch` already computes `available_slots` before analysis and after analysis. When slots are still zero after analysis, it logs internally and emits an operator-visible `ParallelEvent::Log` with `dispatch_capacity_zero_after_analysis`.

That event is useful because it proves the scheduler did analyze newly queued work while correctly suppressing ordinary apply dispatch. But in persistent scheduler loops, the same unchanged zero-capacity state may be observed repeatedly.

## Design decision

Add a small in-memory dedup set for capacity-zero dispatch diagnostics. The key should include the state that determines whether a repeated diagnostic is meaningfully new:

- sorted queued change ids or the analyzer `order`
- `queued.len()`
- `in_flight.len()` or sorted in-flight ids if readily available
- `max_parallelism`
- reason string: `dispatch_capacity_zero_after_analysis`

The implementation should prefer a helper such as:

```rust
emit_dispatch_capacity_zero_diagnostic_once(
    queued,
    in_flight,
    max_parallelism,
    &analysis_result.order,
).await
```

The helper sends the existing `ParallelEvent::Log` only when the key has not been seen. On duplicates it may emit internal `debug!` tracing but must not append another TUI-visible log.

## Constitution compliance

The dedup state is non-authoritative and in-memory only. It does not influence scheduling eligibility, resume routing, acceptance gating, archive routing, or next-action selection. Deleting external state such as `~/.local/state/cflx/**` cannot change the scheduler action for the same workspace contents.

## Why not TUI-only deduplication

The repeating event is generated by the scheduler. Deduping at the source keeps both TUI and any other consumers of `ParallelEvent::Log` from receiving duplicate operator-visible diagnostics, while preserving internal tracing for debugging.

## Why not suppress all future diagnostics

Suppressing the diagnostic once per process would hide meaningful state changes. Signature-based deduplication preserves fresh diagnostics when the queue, in-flight count, or parallelism changes.
