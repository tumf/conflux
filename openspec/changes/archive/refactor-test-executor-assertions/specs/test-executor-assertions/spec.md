## ADDED Requirements

### Requirement: テスト実行基盤アサーションの堅牢化

テスト基盤 (`executor.rs`) におけるエラーは、プロセス全体のパニックではなく、明確なテスト失敗メッセージとして報告されなければならない（SHALL）。

#### Scenario: 不正入力でもパニックせず失敗理由を提示する
- **WHEN** 不正なデータや予期しない状態でエグゼキュータ初期化テストが実行される
- **THEN** `unwrap` によるパニックではなく、`Result::Err` を検証するアサーションとして失敗が報告される
- **AND** 失敗メッセージには失敗理由が含まれる

#### Scenario: アサーションは期待値と実際値を明示する
- **WHEN** executor テスト内の比較アサーションが失敗する
- **THEN** エラーメッセージには期待値と実際値の両方が含まれる
- **AND** 追加の文脈情報（どの条件で失敗したか）を追跡できる
