## Notes

- Scheduler-state correction lives in `src/parallel/queue_state.rs`: `filter_executable_changes` was replaced by `failed_dependency_blocked_candidates` (no local removal) plus `observe_failed_dependency_blocks`, which runs before classification and the debounce gate and emits exactly one `ChangeSkipped` + one `DependencyBlocked` per `(change, failed-blocker set)` epoch. `select_changes_for_dispatch` gained the dispatch gate the removal used to provide.
- Blocker epochs live in `FailedChangeTracker` (`src/parallel/types.rs`) alongside the failed-change set, so both are cleared together and both are ephemeral process state that a restart discards, as `openspec/CONSTITUTION.md` law 1 requires.
- The retry edge is a target-ID-bearing one-shot set on `DynamicQueue` (`publish_explicit_retry` / `drain_explicit_retries`), published from `OperatorCommandService` only when `ReducerCommand::RetryError` returned `ReduceOutcome::Changed`, and consumed by the scheduler loop as Step 0 before reconciliation.
- Truthful blocked termination required a new `SchedulerRunReport::BlockedOrStalled`: a finite blocked-only exit now emits one warning `Log` and no `AllCompleted`. `ParallelRunService::run_parallel` drops the executor before joining its event forwarder, because a terminal path that emits no `AllCompleted`/`Stopped` would otherwise leave that forwarder waiting on a live sender.
- Dispatch coverage boundary: the real-loop regressions assert the scheduler's dispatch *decision* (`select_changes_for_dispatch` selects the independent candidate and never the blocked one) rather than spawning real worktrees and agent subprocesses. Loop tests occupy execution capacity through the existing auto-resolve accounting so the pass stops before workspace creation, which is what keeps the whole `failed_dependency` suite on the sub-second default test path (17 tests in 0.34s).
- Loop drivers synchronise on observed event/analysis counters rather than sleeping blindly: paused Tokio time auto-advances whenever every task is idle — including while the scheduler awaits a real Git subprocess — so a sleep-only driver could cancel a run before its first pass ever executed.
