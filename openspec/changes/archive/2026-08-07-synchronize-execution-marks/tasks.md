## Implementation Notes

- The reconciler lives in `src/orchestration/mark_reconciliation.rs` and is bound to both production dispatch paths: the TUI-local producer loop (`src/tui/runner.rs`) and the orchestration boundary dispatcher (`src/tui/orchestrator.rs`, via `TuiRunSupervisor`). `cflx run` has no operator mark store, so it uses the explicit no-mark binding (`dispatch_event` delegates with `None`).
- `ExecutionEvent::HookFailed` for `on_merged` gained a reducer arm (`src/orchestration/state.rs`) so the merge-wait recovery transition is a reducer-visible *edge*. Without it the "first failure revokes, a replay does not" rule had nothing to compare, and the producer-side pre-application in `src/parallel/queue_state.rs` would have hidden the edge from the dispatcher; both that call and the `RejectionReviewFailed` pre-applications were removed for the same reason.
- `ExecutionMarkStore::replace()` and `AppState::publish_execution_marks()` are now `#[cfg(test)]`. Production writes are target-scoped: operator intent through `OperatorCommandService`, system-driven revocation through dispatch reconciliation.
- `events::dispatch_event` is `#[cfg(test)]` for the same reason: every production dispatch path binds the reconciler and calls `dispatch_event_with_marks`, so a reachable mark-less shorthand would be a second dispatch route that silently skips reconciliation.
- `OperatorFactsStore::record_event` no longer refreshes `latest_activity` for a repeat that carries the same transition and detail. Without that, a duplicate failure advanced a state revision purely on arrival time, which the remote-control-api delta forbids.
