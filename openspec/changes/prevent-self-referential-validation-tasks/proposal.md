# Prevent self-referential final validation tasks

**Change Type**: implementation

## Problem / Context

The `stabilize-parallel-archive-display` change failed archive because `tasks.md` contained a checked implementation task whose purpose was to record final OpenSpec validation for the same change. Evidence validation evaluated that checkbox task and emitted a warning for the task itself. The archive path treated the evidence warning as archive-blocking, so archive promotion did not run and the active change directory remained under `openspec/changes/`.

This creates a self-referential trap:

1. A task asks the implementer to prove final validation.
2. Final validation evaluates all checkbox tasks.
3. The final-validation checkbox is itself evaluated as an implementation evidence task.
4. Archive blocks on the warning generated by the task that exists only to satisfy archive validation.

The user-visible result is confusing: local `cflx openspec validate ... --strict --evidence warn` may print `Validation passed` while archive reports `Validation failed` and preserves the active change directory.

This proposal prevents recurrence by making the validator and bundled guidance reject self-referential final validation checkboxes explicitly, and by providing an archive-equivalent validation mode/message so users and agents can reproduce archive readiness locally.

## Proposed Solution

Implement deterministic, parseable guards for self-referential final validation tasks:

- The native validator detects checkbox tasks in `tasks.md` that require running `cflx openspec validate <same-change>` or recording final OpenSpec validation for the same change.
- Such tasks fail validation with a specific diagnostic that instructs authors to move final validation into a non-checkbox `## Final Validation` section.
- The `cflx-proposal` guidance/templates stop generating final validation checkbox tasks.
- Archive-side guidance and failure reporting recommend the archive-equivalent validation command and identify self-referential validation tasks separately from generic evidence-note failures.
- Provide a local archive-gate validation path, either by adding `cflx openspec validate <change-id> --archive-gate` or by documenting and using `--strict --evidence error` as the exact archive readiness equivalent.

The change must preserve the constitution: validation and archive decisions remain based on repository-verifiable files and git/workspace state, not hidden state.

## Acceptance Criteria

- A change whose `tasks.md` includes a checkbox task requiring `cflx openspec validate <same-change>` as final validation fails validation with a clear self-referential final validation diagnostic.
- The diagnostic tells the author to move final validation into a non-checkbox `## Final Validation` section.
- A non-checkbox `## Final Validation` section that mentions the same validation command is accepted.
- `cflx-proposal` no longer instructs agents to create final OpenSpec validation as a checkbox implementation task.
- Archive-side prompts/errors expose an archive-equivalent local validation command so users can reproduce archive readiness without guessing warning/error policy.
- Existing deterministic evidence validation still accepts ordinary task verification commands such as `cargo test`, `npm run`, and source/test paths.

## Explicit Completion Conditions

- Native validator tests cover same-change final validation checkbox rejection and non-checkbox final validation acceptance.
- Bundled `cflx-proposal` and archive guidance no longer contain examples that place final OpenSpec validation as a checkbox task.
- Archive failure output or prompt guidance names the self-referential validation checkbox pattern when detected.
- The archive-equivalent validation path is documented and covered by CLI or prompt tests.
- Targeted Rust tests for native OpenSpec validation pass.
- Strict OpenSpec validation for this proposal passes without evidence warnings.

## Out of Scope

- Rewriting all historical archived `tasks.md` files.
- Changing ordinary implementation verification tasks that cite runnable tests or commands.
- Relaxing archive validation to ignore evidence warnings silently.
- Introducing durable workflow-control state outside the worktree.
