# 仕様: APIエラーハンドリングの安全化

## 概要
`git_sync` API のエンドポイントは、内部エラーに起因するパニックを起こしてはならない。すべての内部処理エラーは適切に捕捉され、HTTPエラーレスポンスとしてクライアントに通知されなければならない。

## 期待される振る舞い
1. API リクエストの処理中に発生したシステムレベル、または入力に起因するエラーは、サーバーのパニックを引き起こさない。
2. エラー発生時は、HTTP 400 番台または 500 番台の適切なステータスコードと、原因を示すエラーペイロードを返す。

## テストシナリオ (Regression Prevention)
- **シナリオ:** 権限がない、または不正なリポジトリパスを指定して git sync API を呼び出す
  - **手順:** 不正なリポジトリへのパスなど、git コマンドやファイルシステム操作が失敗するような入力を API に送信する。
  - **期待結果:** サーバープロセスがパニック終了せず、正常に稼働を続ける。同時に、クライアントには `500 Internal Server Error` などのエラーレスポンスが、適切なメッセージ(例えば、"Repository not found" や "Sync failed" 等)と共に返される。
