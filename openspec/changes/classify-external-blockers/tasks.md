## Notes

- Task 6 originally read "TypeScript rejects an unknown blocker kind". No gate in this repository runs `tsc`, so a compile-time-only assertion would have been unverifiable and the task text was refined to match enforceable reality. The closed set is enforced where the untrusted server payload actually arrives: `BLOCKER_KINDS` and `toBlockerKind()` in `dashboard/src/api/types.ts`, exercised by `ChangeRow.test.tsx`. The `BlockerKind` union is still declared for editor-level type safety.
- Behavior change: a validated non-repository prerequisite now displays `blocked` with blocker kind `external` instead of `stalled`. Existing tests asserting `stalled` for that case were updated rather than preserved, because collapsing the two is the defect this change removes.
- Behavior change: in parallel dispatch, every acceptance stop that is not a validated external prerequisite — retry exhaustion, no semantic progress, a repeated finding ID, and a repair delta that missed its declared files — now emits an acceptance-phase `ExecutionBlocked` hold and returns a non-error `WorkspaceResult`, so they display `stalled` and keep the worktree preserved. This matches what serial mode already did through `ChangeProcessResult::Stalled`. The two repair-gate stops share `hold_repair_stop` in `src/parallel/dispatch.rs` with the retry-policy stall path, so the two modes cannot diverge again.
- `src/orchestration/blocker_classification.rs` is changed only in service of the finding above: `execution_stop_reason_for` now also maps the repair-gate stop reasons (`repeated_acceptance_finding`, `acceptance_remediation_mismatch`), so the single classifier — not the new dispatch call site — decides the stalled category. Without it a repeated-finding repair stop would silently classify as `no_semantic_progress`.
- Compatibility input parsing is unchanged: `gated` and legacy `blocked` verdict tokens still parse, and a bare token still routes to bounded protocol correction and sets neither lifecycle state.
- `blocker` payloads now require `unblock_condition`. A payload missing it is a protocol error handled by the existing bounded acceptance retry, never an inferred external wait. Both bundled acceptance skills document the five required fields.
